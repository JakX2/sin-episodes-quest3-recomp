# Phase 977: persistent multi-file cache owner

Implement a host-owned persistent scene cache using stable deque rows, filename-handle lookup and independently allocated metadata objects. Native index ensure and native metadata stamp/refresh services remain the executing policy. Engine filename identity is supplied by callback, not invented path normalization. Borrowed metadata remains stable across insertions, selective invalidation triggers only affected file, unknown path fails, clear releases owned sound vectors before objects and can retry after release failure; all access is frozen after partial teardown. The C++ owner is not original CUtlRBTree ABI storage. Host allocator, file stamps, model expansion and refresh are explicit. Loaded test exercises distinct files, alias handle sharing, stale refresh, stable addresses, failed clear/retry and reopening. Explicit clear required before destructor if external cleanup can fail.
