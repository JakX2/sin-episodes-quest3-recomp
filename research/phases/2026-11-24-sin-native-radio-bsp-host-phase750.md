# Phase 750: native radio entity BSP lifecycle composition

Reuse existing SourceMapRuntime (src/source_map_runtime.cpp) and Phase672/674 NativeBehaviorHost. The Phase748 loaded RadioEntityApi already supplies schema, typed key assignment, native spawn/activate and named input; the engine must construct/destroy a real compatible shell through its class factory. New NativeRadioMapHost composes an ordinary ISourceMapEntityHost (or NativeBehaviorHost) rather than registering an invented class alias. Generation-checked attachment and persistent control lookup, fail closed when radio services absent, forward nonradio keys/output connections in original order; engine parser supplies typed radio values using the original ten-entry schema. Native radio spawn/activate replaces generic spawn/activate for radio only, avoids duplicate base calls. Engine owns final destructor, invalidates serial handle; deferred deletion notification removes attachment, dispatcher never clears unrelated handles by index. Explicit typed named input returns unhandled/rejected/failed/applied. No automatic retry after partial native callbacks.

The test explicitly delivers the named Dispatch as an engine I/O observation, not a simulated look trigger or real retail map. Verifies order, base operation counts, native pending handle, Remove, fail-closed missing provider, malformed key rollback, partial removal retry and deferred deletion. Real Source factory registration, parser and queued I/O delivery still host-owned. No original BSP asset found in directly listed owner SE1 folder; fixture is independent authored.
